# TTB Alcohol Label Verifier

AI-assisted prototype for TTB compliance agents. Enter the COLA application fields, upload a label photo, get a per-field **pass / review / fail** verdict in ~2-3 seconds — under the 5-second budget the interviews said was non-negotiable.

**Live demo:** <https://treasury-app-eosin.vercel.app>

## Run it locally

Node 20+ and an [OpenRouter](https://openrouter.ai/) API key.

```bash
git clone https://github.com/s85191939/Treasury-app.git && cd Treasury-app
npm install
cp .env.example .env.local           # paste OPENROUTER_API_KEY
npm run dev                          # → http://localhost:3000

npm test                             # 79 unit tests
npm run test:e2e                     # 5 Playwright tests driving the live URL
```

Default vision model is `google/gemini-2.5-flash` (~2.4 s/label). Swap via `OPENROUTER_MODEL` — any vision + tool-calling model works.

## Approach

- **Next.js + TypeScript + Tailwind on Vercel** — single stateless app, one outbound call. Matches Marcus's "standalone proof-of-concept" framing and his firewall concerns.
- **Vision via OpenRouter** — model-agnostic, swap providers with one env var. Tool/function calling pins the output schema so there's no JSON-from-markdown parsing.
- **The regulatory decision is deterministic TypeScript, not the model.** The model reads text; `src/lib/compare.ts` applies the rules. Same expected/found pair always produces the same verdict, and **84 tests** pin every rule.
- **Fuzzy where Dave wanted judgment, strict where Jenny wanted exactness.** `STONE'S THROW` ≡ `Stone's Throw` (normalised Levenshtein). Government Warning must be canonical text + `GOVERNMENT WARNING:` in caps + bold weight.
- **Beverage-type-aware rules.** Wines under 14% and beer/malt can omit ABV (the spec's *"with some exceptions for certain wine/beer"*); spirits cannot. TTB Standards of Fill (27 CFR 5.203 / 4.72) catch labels with non-approved bottle sizes (e.g. 800 mL Vodka).
- **No persistence, no PII.** Images live for the request lifetime then go away.

## How verification works

| Field | Rule |
| --- | --- |
| Beverage type | Enum match (spirits / wine / beer) |
| Brand / Class / Producer | Normalised Levenshtein — case- and punctuation-tolerant |
| Alcohol Content | Numeric tolerance (±0.05% pass, ±0.3% review). Missing ABV is *N/A* for wine <14% or beer (federal exemption) |
| Net Contents | Parsed mL / L / cL / fl oz; ±0.5 mL pass, ±2% review |
| Standards of Fill | Per-class TTB whitelist of approved sizes — 800 mL spirits fails |
| Country of Origin | Optional (checked only when present in the application) |
| **Government Warning** | Canonical 27 CFR 16.21 text + `GOVERNMENT WARNING:` in caps (hard fail) + bold weight (review — model bold detection is unreliable on real photos) |

The Government Warning bold check was deliberately softened from FAIL to REVIEW after testing against real bottle photographs: vision models routinely misread `bold=false` on legitimate labels, and the previous vendor pilot died on exactly this kind of false-rejection cycle. Caps detection is reliable; bold isn't.

## API

```
POST /api/verify        multipart/form-data
  image=@label.jpg      JPEG/PNG/WebP/GIF, ≤ 8 MB
  application={"brandName":...,"classType":...,"alcoholContent":...,
               "netContents":...,"producer":...,
               "beverageClass":"spirits"|"wine"|"beer"|"unknown",
               "originCountry"?:...}

→ 200 { extracted, results[], overall: "pass"|"fail"|"review", latencyMs }
→ 400 / 413 / 415 / 500 / 502 with a plain-language error string
```

Example:

```bash
curl -X POST https://treasury-app-eosin.vercel.app/api/verify \
  -F 'application={"brandName":"OLD TOM DISTILLERY","classType":"Kentucky Straight Bourbon Whiskey","alcoholContent":"45% Alc./Vol.","netContents":"750 mL","producer":"Old Tom Distillery, Bardstown, KY","beverageClass":"spirits"}' \
  -F "image=@samples/old-tom.jpg"
```

## Test fixtures (`samples/`)

- **8 synthetic labels** generated by `samples/generate.py` — happy path, strict-warning fails (title case + non-bold), ABV exemption boundaries, beer, wine with country of origin, intentional ABV mismatch.
- **1 AI-generated label** (`riverstone-ai.jpg`) — made with Gemini 2.5 Flash Image via OpenRouter. The generator produced typos in the warning text which the verifier correctly catches; closes the spec's *"AI image generation works well for this"* line.
- **13 photo-realistic community labels** in `samples/community/` from [fsyeddev/ttb-label](https://github.com/fsyeddev/ttb-label). 5/5 mismatch fixtures catch the exact field expected; the 800 mL Vodka non-compliance is caught by the Standards-of-Fill check.

`samples/applications.csv` pairs every synthetic image with its application data — drop the folder into batch mode and watch the verdicts come back live.

## Testing

Three layers, all CLI-runnable with no setup beyond `npm install`:

```
npm test          → 79 unit tests across compare.ts, csv.ts, extract.ts (~200 ms)
                     OpenRouter is mocked; pure-function coverage of every rule

npm run test:e2e  → 5 Playwright tests driving the live URL with headless Chromium
                     fills the form, uploads samples, asserts on rendered DOM
                     covers happy path, strict warning fail, wine ABV exemption,
                     Standards-of-Fill non-compliance, batch mode

npm run test:all  → both layers in one shot
```

Unit tests pin the comparator (no mocked decisions). E2E tests prove the deployment actually works end-to-end for a real agent.

## Limitations

- **Vision OCR accuracy is the floor.** If the model misreads, the verdict is wrong. The `notes` field surfaces low-confidence reads.
- **Bold detection on photographs is unreliable** at small font sizes — softened to Review rather than Fail.
- **OpenRouter must be reachable.** Production would need an allowlist for `openrouter.ai`, or a directly-approved provider (e.g. Bedrock GovCloud).
- **No authentication, no persisted audit log.** Per Marcus's "standalone proof-of-concept" framing.
- **Batch concurrency capped at 4.** Production should queue and back off on 429s.
- **CSV pairing is case-sensitive by filename.** Simple; production would join from COLA records directly.
